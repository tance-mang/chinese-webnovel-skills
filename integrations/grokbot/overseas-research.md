# Webnovel Studio 海外创作研究（Grok Bot）

## 元信息（目的、日期、方法、局限）

| 项 | 内容 |
| --- | --- |
| 项目 | Webnovel Studio / chinese-webnovel-skills（https://github.com/tance-mang/chinese-webnovel-skills） |
| 用途 | 可交给 Codex 导入知识库的结构化研究；支撑 `globalize` / `genre-style` / `intimacy` / `native-edit` / `english`（original\|adapt\|translate）/ `submission` / `memory` 等 Skill 升级 |
| 撰写角色 | Grok Bot（海外网文研究员兼英文小说编辑） |
| 查阅日期 | 2026-11-08（Asia/Shanghai） |
| 报告语言 | 简体中文为主；平台名、类型名、政策术语保留英文 |

### 目的

为中国作者的双语出海能力提供可溯源资料：平台规则差异、类型叙事习惯、亲密情节叙事功能、中英改编原则、翻译腔/AI 模板识别特征，以及建议写入 Skill 的可配置规则。本报告**不是**机械模仿特定作家的指令，也**不是**法律意见。

### 方法

1. 优先打开官方 Content Guidelines / Help Center / Terms / Knowledge Base。
2. 次选平台品牌材料（如 Wattpad Media Kit）、行业观察（Writer Beware、Publishers Weekly）与公开作者经验；一律标注可靠性分级。
3. 区分三类陈述：**平台政策**、**作者社区经验**、**个人/编辑归纳**。
4. 不虚构热度、销售数据或「读者一定喜欢 X」；无可靠来源标「待核实」。
5. 不复制受版权保护小说的大段正文；反例均为自造短句。

### 局限

- 平台政策会更新；引用以查阅日页面为准，投稿前必须再核官方页。
- Webnovel 公开 AI 政策表述碎片化；签约条款以作者实际合同与官方文本为准，本报告仅引用公开评论与 ToS 概要。
- 读者群体描述仅引用可公开材料；许多「读者偏好」无法量化，标为经验归纳。
- 亲密情节指导服务于 Romance 叙事功能与平台合规提示，**不**用于绕过模型或平台政策。

## 类型风格档案

> 下列为 **类型惯例归纳**（编辑/作者指南与社区经验），**不是**平台强制政策，除非另行标注。用于 `genre-style` 可配置 profile，禁止写成全英文统一硬规则。

### A. Dark Romance

| 配置项 | 建议 |
| --- | --- |
| 读者期待 | 危险关系、权力不对等、道德灰度、欲望与心理博弈；常期待高强度情绪与「黑暗」氛围，但仍要角色能动性与后果。 |
| 节奏与 POV | 常 deep POV（第一或极近第三）；场景可更密、更压迫；「慢」来自抵抗与恐惧，而非日常误会。 |
| 对白 | 威胁、试探、控制与反击并存；潜台词重于俏皮拌嘴。 |
| 亲密/张力功能 | 亲密场景服务权力转移、信任破裂/重建、创伤回应；不是装饰性插入。 |
| 同意与边界 | 读者期待复杂，但创作指导仍应明确：角色年龄成年；区分角色行为不道德 vs 叙事美化伤害；内容警告必要。平台侧：RR 几乎不适合作为主场；Wattpad/Inkitt/KDP 各有上限。 |
| 常见 AI 缺陷 | 暴力+情欲标签堆砌；男主「占有」口头禅循环；无后果的 dubcon；女主工具化。 |
| 相对差异 | 比 Contemporary 更依赖威胁与道德张力；比 Thriller 更以关系为引擎。 |

（参考类型：编辑向指南与学术/行业对 dark romance 的讨论，如公开文章对 consent 与权力结构的分析——属作者社区/编辑经验，非平台政策。）

### B. Contemporary Romance

| 配置项 | 建议 |
| --- | --- |
| 读者期待 | 当代现实感、可信对白、关系成长、情感细节；结局常朝向 HEA/HFN（类型惯例，非硬性法律）。 |
| 节奏与 POV | 允许中长句与生活场景；节奏可慢热；双视角常见。 |
| 对白 | 自然、有性格声音、可有幽默；避免「说明书式表白」。 |
| 亲密/张力 | 暧昧来自选择与脆弱，而非持续威胁；身体亲密推进关系阶段。 |
| AI 缺陷 | 千篇一律咖啡店遇见；情感总结句（「she felt a myriad of emotions」）；强行每 200 词一个钩子破坏生活感。 |
| 相对差异 | 比 Dark 更需要日常可信度；比 Slow Burn「标签」更宽（可含慢热，但不必须）。 |

### C. Slow Burn Romance

| 配置项 | 建议 |
| --- | --- |
| 读者期待 | 推迟满足，但持续升温；几乎亲吻/几乎坦白的循环要有信息增量。 |
| 节奏 | 亲密暴露阶梯：意识 → 抵抗 → 裂缝 → 投降；每场改变「知道/想要/害怕」之一。 |
| 张力手法 | 靠近与后退交替；具体照顾、记住细节、未说出口的句子；禁止无进展的拖字。 |
| AI 缺陷 | 用「时间跳跃」假装慢热；重复同一误会三次；无身体/情绪升级的纯误会肥皂。 |
| 字数感 | 作者经验常认为需要足够篇幅承载升温（具体市场字数因平台而异，**不编造统一字数门槛**）。 |

### D. Psychological Thriller

| 配置项 | 建议 |
| --- | --- |
| 读者期待 | 不可靠叙述、认知偏差、动机迷雾、可回看的公平线索；反转需事后成立。 |
| 节奏与 POV | 近距离 POV 利于隐瞒与误导；章节可短、切场快，但要有「压力沉降」段，避免机械每段钩子。 |
| 对白 | 潜台词、答非所问、信息差；少用全知解说。 |
| 与 Romance 交叉 | Romantic suspense 可有关系线，但引擎仍是威胁与真相，不是 HEA 公式。 |
| AI 缺陷 | 为反转而反转；隐藏关键信息却无铺垫；每章末句强制 cliffhanger 导致审美疲劳。 |

### E. LitRPG

| 配置项 | 建议 |
| --- | --- |
| 读者期待 | 可见的系统/数值/技能；升级改变战术；规则一致；成长可预期又有代价。 |
| 节奏 | 战斗/任务/结算循环；重大升级宜绑剧情拐点；状态栏只展示影响当前场景的信息。 |
| 对白 | 可偏功能性；队友战术交流；避免长篇系统说明书对白。 |
| 平台 | Royal Road 社区经验高度契合（作者社区经验）。 |
| AI 缺陷 | 无意义刷屏状态窗；技能名中英混杂无 glossary；数值膨胀无代价；「ding」无场景后果。 |

### F. Progression Fantasy

| 配置项 | 建议 |
| --- | --- |
| 读者期待 | 长期力量/地位/认知上升曲线；世界规则清晰；挑战升级。 |
| 与 LitRPG | 可无显性 UI；更偏修炼/训练/领悟；东方玄幻出海常落此桶。 |
| 节奏 | 里程碑式突破；中间层用小型胜利维持；不必言情式情绪节拍。 |
| AI 缺陷 | 境界名每章改译；突破描写套话（金光一闪）；反派排队送经验。 |

## 中英叙事差异与反例

### 1. 总体差异（原则级，避免东西方二分）

| 现象 | 中文网文常见动能 | 英文连载/类型市场常见读法 | 改编原则 |
| --- | --- | --- | --- |
| 信息密度 | 章内讲解境界、势力、称号 | 读者更耐受「先场面后规则」或 glossary 外置 | `adapt`：首 3–5 章降讲解密度；规则用行动演示 |
| 情绪外放 | 内心独白、义愤、打脸旁白 | Romance 重 show；Thriller 重不可靠；LitRPG 重系统反馈 | 按目标类型改「叙述距离」而非删动机 |
| 钩子 | 章末强悬念、卡点付费 | RR/Wattpad 仍爱章末拉力，但 Romance 过密钩子会假 | 类型配置「章末拉力强度」滑杆 |
| 对白 | 称号、辈分、讽喻成语 | 口语节奏、打断、潜台词 | 保留关系层级，改成英语里能听出权势的说法 |
| 幽默 | 梗、弹幕感、网络热词 | 时效梗易失效；需可迁移幽默 | 社交梗进「保留/替换/脚注」决策表 |

### 2. 中国网文套路：保留 vs 本地化（非固定删改清单）

| 元素 | 常可保留（尤其 `translate` / 保留中国背景） | 常需本地化或解释（`adapt`） | 决策提示 |
| --- | --- | --- | --- |
| 家族称谓（大哥/姐姐/叔叔） | 作为权力与亲密结构 | 纯字面 Brother 可能丢失辈分政治 | 用关系功能翻译 + 首次行动演示 |
| 彩礼/婚约/相亲 | 可保留为中国社会情节 | 转欧美背景时改「匹配机制」但勿偷改人物动机 | 改编清单标「文化制度」 |
| 修仙境界 | 语义化稳定英译 + 总表 | 每章换译名是大忌 | `memory` 锁定术语表 |
| 宗门/面皮/打脸 | 可保留为 Progression 社交货币 | 需让英语读者懂「为何必须当众」 | 用观众/资源后果写清 |
| 系统流/签到 | 可直通 LitRPG | UI 格式符合英文社区习惯 | 状态栏短、相关才贴 |
| 国内社交梗/平台名 | 保留中国背景时可留 | 出海混合背景常替换等效行为 | 勿用过时英美梗硬替 |

**三条创作路径（对应 Skill）：**

1. `original`：按目标 genre profile 直接英文写。  
2. `adapt`：保核心因果与人物动机；文化层可选「保留中国 / 混合 / 转目标文化」；先出决策表再改正文。  
3. `translate`：保事实与声音；优先自然英语，不擅自改情节。

### 3. 翻译腔 / 机械句式 / AI 模板：可观察特征与自造反例

| 特征 | 为何容易引起英语读者反感 | 自造反例（差） | 自造改进方向（好） |
| --- | --- | --- | --- |
| 情感总结清单 | 告诉情绪而非经历 | "She felt angry, sad, and strangely hopeful." | 用一个具体动作/身体细节承载 |
| not X, but Y 模板 | AI 高频修辞 | "It was not love, but something darker." | 偶尔可用；段段出现则删 |
| 整齐三项列举 | 节奏假工整 | "He was tall, dark, and handsome." | 打破对称或改具体 |
| 感官清点 | 紫散文库存 | "The aroma of coffee filled the air as golden sunlight spilled…" | 只留推动情节的 1 个感官 |
| 同一句长波 | 催眠 | 连续五句主谓宾同构 | 故意长短交错 |
| 章末假钩子 | 廉价悬念 | "Little did she know, everything was about to change." | 用具体未解问题收束 |
| 称谓直译腔 | 关系失真 | "Good morning, Elder Sister Zhang." 无语境反复 | 首次建立关系后改自然称呼策略 |
| 境界说明书 | 像补丁 | "Foundation Establishment is the second stage…" 大段 | 用对比与代价嵌入场景 |

> 说明：以上为编辑可观察特征归纳（作者社区/编辑经验），**不能**宣称可可靠鉴定「是否 AI 创作」。`native-edit` 应输出「问题位置 / 理由 / 候选改法」，由作者选择。

## 成年角色亲密情节写作指导

> 面向 `intimacy` Skill。仅用于成年角色 Romance/关系叙事。平台合规检查**独立于**模型是否愿意生成。

### 1. 叙事功能（先问「这场推进什么」）

| 功能 | 适用类型倾向 | 场景后应留下的变化 |
| --- | --- | --- |
| Romantic Tension | 全 Romance | 吸引力↑ 或 自我防备↑ |
| Emotional Intimacy | Contemporary / Slow Burn | 秘密、恐惧或需求被看见 |
| Sensual Atmosphere | Contemporary / Dark（程度不同） | 身体意识改变选择 |
| Power / Fear Dynamics | Dark Romance | 权力天平或道德代价变化 |
| Comfort / Aftermath | 全类型 | 信任修复或新裂痕 |
| Fade to Black | 全类型；RR 等受限平台优先 | 关系阶段仍须前进 |

### 2. 表现方式光谱（配置项，非绕过政策）

1. **暗示 / 留白（Fade to Black）**：镜头离开；用前后情绪与关系后果完成。  
2. **感官暧昧（Sensual）**：触、气息、距离、未完成动作；焦点在主观体验与选择。  
3. **明确成人描写**：仅当目标平台允许且评级正确；仍须服务人物，而非清单式动作堆砌。

### 3. 必填配置维度（给 Codex 做成 schema）

- 风格：Dark / Contemporary / Slow Burn / …  
- 场景目的：张力 / 信任 / 冲突转折 / 安慰 / …  
- 表现方式：暗示 / 感官 / 明确 / Fade to Black  
- 关系阶段：陌生 / 试探 / 承诺前 / 承诺后 / 破裂后  
- 心理状态：双方各 1–2 个主导情绪  
- 同意与边界：双方成年确认；自愿/协商/拒绝权在场（Dark 中「角色违背道德」≠「作者删除边界提示」）  
- 目标平台限制：自动载入平台档案（尤其 RR / Tapas App / Wattpad Mature vs Banned）  
- Aftermath：关系事实如何变（必须非空）

### 4. 分类型要点

- **Contemporary：** 亲密常是脆弱与幽默的交换；事后日常细节增强真实。  
- **Slow Burn：** 身体进度不得跑赢情绪进度太远；几乎触碰要有信息增量。  
- **Dark：** 危险与欲望交织时，仍需角色主体性；内容警告；仔细选平台（RR 不适合情色核心）。  
- **Thriller 交叉：** 亲密可被用作操控或误导，但需公平线索，避免无叙事功能的剥削镜头。

### 5. 明确不做的事

- 不把「模型拒绝」自动路由到另一模型以规避政策。  
- 不生成涉及未成年人的性内容。  
- 不把平台禁止项写成「可开关的风格滤镜」。

## 建议新增/调整的 Skill 规则

### 1. `genre-style`（新建）

- 数据驱动 `genre profile` JSON/YAML：受众期待、POV、节奏、对白、情绪、章推进、文化注意、AI 常见缺陷、平台适配、正反例。  
- 首批：Contemporary Romance、Dark Romance、Slow Burn Romance、Psychological Thriller、LitRPG、Progression Fantasy（可扩 Romantic Suspense 等）。  
- **覆盖**全局短句比例等机械规则。

### 2. `globalize`（新建）

- 输入中文章节 + 模式（保留中国 / 混合 / 转背景）。  
- 输出：文化改编决策表（称谓、货币、婚俗、教育、法律、梗、境界术语）+ 对动机/因果的影响标记 + 待作者确认。  
- 禁止擅自改核心动机与事件因果。

### 3. `english` 升级：`original` | `adapt` | `translate`

- 三入口分离系统提示与验收标准。  
- `adapt` 绑定 `globalize` 决策表。  
- `translate` 绑定术语表锁定。

### 4. `intimacy`（新建）

- 使用上一节 schema；生成「场景任务卡」而非固定肉戏模板。  
- 调用前读平台档案；RR 默认限制性内容为核心。

### 5. `native-edit`（新建）

- 检测：Translationese、Cultural Mismatch、Voice、Dialogue、Genre Conformity、POV/Tense、Rhythm、Emotional Continuity。  
- 输出分级：客观错误 / 编辑建议 / 主观风格。  
- **禁止**声称「AI 鉴定准确率」。

### 6. `submission` 升级

- 平台包：书名、简介、标签、内容警告、AI 使用记录、评级建议。  
- 内置对照表；**Radish = 历史，不推荐**。  
- KDP：强制 AI-generated 披露检查清单。  
- Tapas：AI 生成则阻断推荐。  
- Webnovel：合同/独家风险提示 + AI 政策待核实警告。

### 7. `memory` 升级

- 双语角色卡、文化设定、术语表、已确认改编决策、平台目标。  
- 亲密关系阶段状态机（供 `intimacy` 读取）。

### 8. 质量相关旧 Skill

- `deslop` / `human` / `aidetect`：英文侧改为「特征启发式 + 人工确认」，与 `native-edit` 对齐，避免伪科学鉴定。  
- `review`：按 genre + 平台评分轴评分。
